Пожелания владельца для следующей переработки сайта. Реализация ещё не выполнена; объём и способ выполнения нужно уточнить перед началом работ.

- Добавить проверку Python-кода ученика прямо на сайте: редактор решения, кнопку «Проверить решение», выполнение тестов над введённым кодом и понятный отчёт об успехах и ошибках. Существующая онлайн-самопроверка оценивает ответы на вопросы; проверки Python сейчас запускаются отдельно через pytest.
- Для каждого учебного бизнес-процесса предусмотреть отдельные проверки и тесты: успешный сценарий, отказ, граничные значения, ожидаемые исключения и состояние объектов после операции. В частности, при отказе оплаты проверять сохранность баланса и отсутствие записи успешной транзакции.
- Добавить подсказки к заданиям: что реализовать, какой результат ожидается и как проверить решение.
- Объяснить назначение `...` в примерах. В `Protocol`, включая `PaymentStrategy.process`, это допустимое описание контракта; реализацию показывать в конкретных классах. В учебных заготовках явно обозначать места для самостоятельной реализации. Не считать любое троеточие ошибкой.
- Добавить UML-диаграммы к учебным материалам. Предлагаемый старт: диаграммы классов с контрактами и реализациями, а также диаграммы последовательности для успешной оплаты и отказа. Связывать диаграммы с соответствующими примерами кода и обновлять вместе с ними.
- Переработать учебный путь сайта так, чтобы объяснение, диаграмма, задание, подсказки и проверка решения были связаны между собой.

- Напоминание владельцу: склонировать репозиторий преподавателя и передать ссылку на него или путь к локальной копии в этот чат. Репозиторий пока не предоставлен и не исследован.

По сообщению владельца, на сайте преподавателя каждый бизнес-процесс имеет проверки и тесты. На предоставленном скриншоте видны бизнес-правила, редактор `solution.py`, кнопка «Проверить решение» и отчёт «Результаты автопроверки (pytest sandbox)» с именами тестов и ошибками. Это ориентир для учебного сценария: ученик пишет код, запускает его проверку на странице, читает результат, исправляет решение и проверяет повторно.

Проверка непосредственно через сайт подтверждена как желаемый результат. Скриншот не определяет, где исполняется Python — в браузере или на сервере, — и сам по себе не подтверждает полноту покрытия всех бизнес-процессов.

Перед реализацией уточнить:

- Нужна ли полностью локальная работа в браузере или допустим сервер для выполнения проверок? Установка Python учеником не должна быть обязательной для проверки через сайт.
- Начать со второй недели и стратегий оплаты или охватить обе недели?
- Какие UML-диаграммы обязательны по требованиям преподавателя?

Среда выполнения Python и конкретная технология проверки пока не выбраны.
