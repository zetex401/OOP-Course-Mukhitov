# Challenge — «Что может сделать завершение небезопасным или избыточным?»
> Goal: завершить настроенный TFW рабочий след, не выдумывая детали будущего сайта.

## Consistency Check
Измерения Gather: (A) значения проекта подтверждены, (B) выбранный адаптер ещё не применён к target, (C) будущие продуктовые детали оставлены открытыми.

### Несовместимые сочетания
| Измерение A | Вариант | Измерение B | Вариант | Причина |
|---|---|---|---|---|
| B | target ещё отсутствует | процедура | повторная чистая Full Init поверх текущего настроенного состояния | Init Step 0 запрещает Full Init поверх receiver config/state/trace; повторная инициализация/сброс повредит state и уже выбранные решения. |
| A | `.tfw/` sources изменены и происхождение ранее отмечено неизвестным | установка | blind overwrite/copy поверх тех же исходников или соседей | Init и TRACE требуют classify ownership, сохранить локальные данные; простое наличие target/source не подтверждает ownership. |
| C | вопросы сайта открыты | конфигурация | домыслить framework/build/test/stacks settings | противоречит North Star/TRACE и создает неподтвержденные обязательства. |

### Сохранившиеся конфигурации
| Конфигурация | Решения | Адаптер | Открытые детали | Вывод |
|---|---|---|---|---|
| C1 | Подтверждённые локальные значения | Codex targets после точной классификации | Остаются открыты | Разрешённый путь завершения с проверкой idempotence |
| C2 | Те же | Считать текущее состояние clean install и заново создавать все | Заставить определить сайт | Отклонить: конфликт с существующими files/trace и неизвестными product decisions |

**Неожиданно сохранившиеся варианты:** C1 полон, даже если product requirements сайта остаются открытыми: настройка TFW задаёт метод и маршруты, а не спецификацию будущего сайта.

## Findings
### C1: основной риск — происхождение текущего состояния, не неизвестность продукта
`.tfw` уже содержит config, workflow, tasks, init task и изменённые файлы относительно Git; `TRACE.md` прямо фиксирует отсутствие исходного baseline. Поэтому безопасное завершение требует не очищать/переинициализировать проект, не объявлять удалённый state известным и проверять конкретные принимающие target routes/blocks перед изменением.

### C2: не создавать ложные блокировки
Отсутствие app code означает, что проектные build/test команды остаются пустыми. Официальный upstream README определяет TFW Full через формальные research/evidence/review/knowledge gates, но не требует закрыть будущую продуктовую спецификацию перед настройкой: https://github.com/saubakirov/trace-first-starter. Локальные North Star и Init workflow имеют приоритет для конкретного проекта.

### C3: identity/authorization checkpoint
`team/ars.md` сам говорит, что профиль — attribution, не authentication. При этом task status указывает owner `ars`, `upstream_route: owner:ars`, `activation: owner-only`, а TRACE сохраняет явное согласие пользователя на Full Init; в этой беседе владелец ещё раз явно разрешил необходимые шаги и подтвердил. Это достаточно как текущая owner-direct авторизация для предусмотренной процедуры, без придумывания технических полей профиля. Coordinator должен продолжать под зарегистрированным owner route; профиль не преобразовывать в механизм аутентификации.
