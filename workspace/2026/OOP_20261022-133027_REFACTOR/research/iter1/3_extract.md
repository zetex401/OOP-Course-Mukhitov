## Findings

### E1. Точный runtime-кандидат и повторный запуск

[Официальная страница размещения](https://pyodide.org/en/stable/usage/downloading-and-deploying.html) указывает CDN release и возможность собственного размещения. Фактический HTTPS GET [v314.0.7/full/pyodide-lock.json](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide-lock.json) вернул 200, 119077 bytes по RawContentLength; SHA-256 UTF-8 текста ответа: `5dc2fc119108bc148c7457dc86e7675b5c87e1cafd420b9c34c1eaef7b36c010`. Поля info: Python 3.14.2, ABI 2026_0, wasm32, emscripten_5_0_3. Pytest: 9.0.2, pytest-9.0.2-py3-none-any.whl, SHA256 `88b9f5fbf0e425844c0909772952a8c43d5aacbd33e5b9ef821bc6a4c7e53b82`. Зависимости перечислены lock-файлом. Это доказательство доступности метаданных, ещё не загрузки/работы WASM.

[pytest usage](https://docs.pytest.org/en/stable/how-to/usage.html) допускает pytest.main с явными аргументами и возвращаемым exit code, но предупреждает о кэшировании импортов при повторном вызове в процессе. Следствие анализа: для D2=B недостаточно перезаписать текст файла; нужны проверенные очистка sys.modules/pytest-контекста или пересоздание среды. Для D2=A очистка Python-процесса следует из нового runtime, но время и память надо измерить. Это сравнение свойств, не итоговый выбор.

[Worker.terminate](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate) прекращает worker сразу, не ожидая завершения его операций. Следствие для нашего UI: текст редактора и состояние страницы должны жить вне worker; после отмены создаётся новая среда, старые сообщения не принимаются. Метод не является обещанием жёсткого глобального лимита памяти браузера. Прерывание через SharedArrayBuffer из Gather остаётся отдельным механизмом с требованиями к headers.

### E3. Схема минимальной воспроизводимой пробы Challenge

Пробы исполняются только после следующего gate. Все файлы/логи — system temp/tfw/OOP_20261022-133027_REFACTOR с отдельным подкаталогом researcher, удаляемым после извлечения результата. Продуктовые файлы только читаются. Параметры ниже исследовательские, не утверждённый SLA будущего сайта.

1. **Контроль CPython:** скопировать неизменные W1 reference/test и W2 solid_demo/payment_methods/test_terminal в временные папки; выключить запись pyc, pytest plugin autoload и cacheprovider. Записать runtime/pytest версии и exit/counts. Это эталонная контрольная точка совместимости, не доказательство browser UI.
2. **Browser harness:** статическая локальная страница с textarea/Run/Stop/результатом и счётчиком отклика; module worker с pinned Pyodide 314.0.7; загрузить pytest из lock. Загрузка выполняется отдельно от тестового лимита. Плановый предел загрузки 60 s, исполнения 5 s; отдельно измерить фактическое превышение, не объявлять их пользовательскими нормативами.
3. **W1 ввод:** байты textarea записать в /work/solution.py, WEEK1_MODEL=solution, explicit sys.path; загрузить test_reference без fallback к reference_solution. Получить module path, hash текста, exit code и реальные отчёты тестов. Повторить с независимым domain-пакетом из сохранённого walkthrough/учебного каркаса, если выбирается многофайловый формат. Не выдавать эталон за работу ученика.
4. **W2 ввод:** подставить редактируемые solid_demo/payment_methods (или явно отображённые модули) и проверить 14 provided случаев. Отдельный собственный StudentFareService + внешняя сборка подаёт STUDENT-ID; oracle проверяет 50/100 и точный amount в payment/repo. Отсутствующий student_fares должен давать ошибку/незавершённость, не зелёный fallback.
5. **Отрицательные образцы:** W1 изменить баланс до InsufficientFundsError, раскрыть изменяемый stops либо допустить age=60:00; W2 записать успех при False, вызвать fares при unready, изменить баланс при отказе, всегда возвращать обычный тариф. Каждый изменённый вариант должен провалить соответствующий oracle. Эти mutations существуют только во временных копиях.
6. **Повтор и ошибки:** bad→fixed→bad текст в отдельных запусках с distinct ID/hash; синтаксическая ошибка; пустой тестовый набор/collection error не считаются успехом; бесконечный while True; Stop; автоматический timeout; новый успешный запуск после обоих; контролируемый неправильный URL runtime даёт environment error и возможность retry. Объём вывода ограничивается, переполнение не должно блокировать UI.
7. **Наблюдение UX/нагрузки:** отдельно cold startup, cached повтор, pytest time, суммарный wall time, browser version и viewport; heartbeat/кнопка в момент loop проверяет отзывчивость. Один компьютер и доступная сеть не доказывают поведение всей группы, мобильных устройств или реального hosting. При недостатке browser-инструмента указывать missing evidence, не заменять browser результатом Node.

Уточнённые oracles для пробелов Gather:

- Нехватка карты W2: после отказа charge(100) при балансе50, charge(50) обязан вернуть True, затем charge(0.01) обязан вернуть False. Это проверяет наблюдаемое сохранение остатка без добавления нового публичного getter; прямой snapshot _balance допустим только как дополнительное наблюдение временного эксперимента, не новый контракт API.
- Unready: fares spy увеличивает counter/бросает AssertionError при compute_fare; ожидается ноль вызовов, как и scan/payment.
- Ошибка pytest: exit0 + реальные собранные/пройденные случаи, отсутствие неожиданных skipped/error. Статическая надпись PASS и отсутствие тестов не удовлетворяют HL.

TD-004: общий локальный маршрут node tests + обязательные Python contract/student/guided/week2 сценарии + материалы + build + browser runner/diagram проверки. Проверяющий должен видеть ненулевой итог при любом обязательном сбое.

UML: W1 — Route/Bus/Card/Ticket, связь Bus→Route и validate(Ticket,Bus) без автоматической посадки. W2 — шесть зависимостей TransitTerminal, структурное выполнение Protocol конкретными классами, отдельный FareCalculator/StudentFareService и PaymentStrategy. Sequence: ready→scan→fare→process; True→record_success→green→success; False→red→error; unready завершается до scan/fare/pay. Diagram oracle проверяет реальные имена и читабельный результат на узком/широком экране; рисунок не заменяет объяснение. Нужны явные подписи «контракт», «предоставлено», «реализовать самостоятельно».

H3: удаляемыми могут быть только реально обнаруженные воспроизводимые кэши. В выделенной копии их не было; отсутствующие файлы не создаются ради демонстрации чистки.
