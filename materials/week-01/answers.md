# Ответы и разбор WEEK1

После собственной попытки. У каждого компонента одно основание 0/1; пороговых ярлыков освоения нет. Онлайн-выбор не доказывает самостоятельный код или свободное объяснение.

## Основы · 8 баллов

### Bus — класс; a = Bus(...), b = Bus(...) с одинаковыми данными. Что верно?

Верно: B — Это два экземпляра; равные данные не делают их одним объектом.

Класс задаёт устройство экземпляров. Два вызова создают разные объекты; идентичность отличается от равенства состояния. Один балл только за этот компонент.

### Какой инвариант пассажиров автобуса верен после успеха и отказа?

Верно: C — 0 <= current_passengers <= capacity.

Пустой автобус допустим. Отказ тоже обязан сохранить число в допустимых границах. Один балл только за этот компонент.

### Кто должен проверять баланс и менять его при оплате?

Верно: A — Метод карты pay(fare).

Карта объединяет правило и изменение состояния. Это Tell, Don’t Ask; чтение balance для отчёта остаётся допустимым. Один балл только за этот компонент.

### Что означает поле _balance в Python?

Верно: B — Это соглашение о непубличной детали, а не запрет намеренного доступа.

Подчёркивание обозначает внутренний интерфейс. Property без setter ограничивает обычное публичное присваивание, но Python не становится песочницей. Один балл только за этот компонент.

### Как задать точную десятичную сумму 0.10?

Верно: C — Decimal("0.10").

Строка сохраняет десятичную запись. Decimal из float получает уже существующее двоичное приближение. Один балл только за этот компонент.

### Тариф Decimal("100.00"), скидка Decimal("0.25"). Сколько спишет активная карта с достаточным балансом?

Верно: A — 75.00.

Скидка — неоплачиваемая доля: 100 × (1 − 0.25) = 75. Полная скидка даёт нулевую сумму, но не отменяет блокировку. Один балл только за этот компонент.

### Чем полезен InsufficientFundsError в контракте pay?

Верно: B — Различает причину отказа; код должен сам сохранить баланс.

Исключение сообщает причину. Оно не откатывает присваивания: проверка достаточности должна стоять до списания. Один балл только за этот компонент.

### Как проверять срок билета без ожидания 60 минут?

Верно: C — Передать фиксированные aware issued_at и now.

В учебной адаптации явное now делает границы воспроизводимыми. В рабочем вызове now можно не передавать; используется UTC. Один балл только за этот компонент.

## Случай 1 · Ошибка карты · 3 балла

### Как клиент обходит инвариант?

Верно: B — Публичное присваивание balance позволяет записать -1.

Свободная публичная запись обходит доменную операцию. Нужен интерфейс чтения и проверенные top_up/pay. Один балл только за этот компонент.

### Баланс до pay равен 50.00, пытаются списать 100.00. Ошибочный метод меняет баланс, затем бросает исключение. Что осталось?

Верно: A — -50.00: исключение не отменяет присваивание.

Списание до проверки оставляет -50.00. Само возникновение ошибки не восстанавливает состояние. Один балл только за этот компонент.

### Какой порядок защищает исправный pay?

Верно: C — Проверить блокировку/тариф/скидочную сумму/остаток → изменить баланс → вернуть сумму.

Все причины отказа проверяются до изменения. При нехватке допустимый старый баланс сохраняется. Один балл только за этот компонент.

## Случай 2 · Билет · 3 балла

### Отдельный новый билет: is_validated=False, возраст 10 минут, допустимый Bus. validate(bus) даёт…

Верно: A — Успех; is_validated=True.

Новый непросроченный билет становится использованным только после успешных проверок. Один балл только за этот компонент.

### Отдельный билет уже использован в Bus A: is_validated=True, возраст 20 минут. Проверяют в Bus B. Результат?

Верно: C — TicketAlreadyUsedError; True.

Одноразовость принадлежит всему билету, а не паре билет/автобус. Отказ сохраняет True. Один балл только за этот компонент.

### Отдельный новый билет: is_validated=False, возраст ровно 60:00. Допустимый Bus. Результат?

Верно: B — TicketExpiredError; False.

В этой явной адаптации верхняя граница исключена. Первая просрочка отвергается до изменения, поэтому False сохраняется. Один балл только за этот компонент.

## Случай 3 · Коллекция Route · 3 балла

### Что произойдёт после route.stops.clear()?

Верно: C — Внутри маршрута останется 0 остановок: инвариант нарушен.

Отсутствие setter запрещает замену свойства, но не изменение объекта, на который оно ссылается. Один балл только за этот компонент.

### Как защитить и входную ссылку, и выдаваемое значение?

Верно: A — Скопировать нормализованные строки в tuple и возвращать его.

Копирование отделяет входной список; tuple со строками нельзя очистить через публичный интерфейс. Один балл только за этот компонент.

### Какое наблюдение обнаруживает утечку входного списка?

Верно: B — Создать Route из stops, очистить stops, проверить route.stops == ("A", "B").

Проверяется состояние после внешней мутации. Дополнительно нужно проверить, что выдаваемое значение тоже нельзя разрушить. Один балл только за этот компонент.

## Случай 4 · Переполнение Bus · 3 балла

### Какой исход требует контракт?

Верно: B — CapacityExceededError.

9 + 2 > 10, поэтому посадка отвергается доменным исключением переполнения. Один балл только за этот компонент.

### Сколько пассажиров должно остаться после отказа исправного метода?

Верно: C — 9.

Отклонённая операция не добавляет людей и не обнуляет салон. Прежнее значение 9 сохраняется. Один балл только за этот компонент.

### Какой тест поймает метод, который сначала добавил людей, затем бросил ошибку?

Верно: A — pytest.raises(CapacityExceededError) и затем assert bus.current_passengers == 9.

Одно исключение не доказывает сохранность. Assert после отказа обнаружит оставшиеся 11 пассажиров. Один балл только за этот компонент.
