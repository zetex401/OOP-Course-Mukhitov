# Практика недели 1. Полная модель Avtobys

Результат — ваша Python-модель четырёх сущностей, свои тесты и объяснение инвариантов. [Маршрут](README.md) описывает предусловия, источники и предоставленную помощь C16-V.

## Практика: 60 минут

| Минуты | Работа и наблюдаемый результат |
|---|---|
| 0–5 | Создать папку из starter; прочитать helpers и отличие данного от своего |
| 5–25 | Реализовать Route/Bus: создание, свойства, связь, посадка/высадка; проверить внешнюю коллекцию и отказ |
| 25–55 | Реализовать Card/Ticket: создание/чтение/переходы, обе block-операции, скидку/срок; показать успех/отказ |
| 55–60 | Начать собственные пять тестов с исходного состояния и наблюдаемого результата |

## Самостоятельная работа: ещё 60 минут

| Минуты | Работа и наблюдаемый результат |
|---|---|
| 0–15 | Закончить свои пять сценариев и дополнительные границы раздела 6 |
| 15–30 | Выполнить свои тесты, демонстрацию и справочные проверки своей модели; исправить/повторить |
| 30–40 | README, ручная рубрика и четыре вопроса защиты: объяснить, показать успех и отказ |
| 40–60 | Полная онлайн-попытка, разбор ошибок и сохранение итога в разделе «Результаты» |

Два рабочих часа включают 50 минут модели, 20 минут своих тестов, 15 минут запуска/отладки, 10 минут README/защиты, 20 минут онлайн-разбора и 5 минут каркаса = 120. Это план без свободного резерва, не измеренный темп новичка и не доказанная экономия валидаторов. Незавершённое укажите с фактической причиной/временем; полного прохождения тогда ещё нет. Композиция/полиморфизм комплектов 2–3 не требуются.

## Создать свою папку

Скачайте starter.py в удобное место, затем:

```powershell
python starter.py lab01_transit_domain
cd lab01_transit_domain
python -m compileall -q domain
python -m pytest tests/ -v
```

Последняя команда сначала не содержит тестов и не подтверждает готовность. Реализуйте все методы с NotImplementedError и напишите свои tests/test_domain.py. Не перезаписывайте существующую работу: generator откажется от уже существующей папки. Каркас даёт проверки/сигнатуры, но не готовые классы. В domain/__init__.py экспортирован общий публичный интерфейс; подробное разбиение соответствует исходной лабораторной.

## 1. Подготовьте папку

```text
lab01_transit_domain/
  domain/
    __init__.py
    route.py
    bus.py
    card.py
    ticket.py
  tests/
    test_domain.py
  README.md
```

В каркасе `domain/__init__.py` экспортирует четыре класса и исключения для команды проверки `WEEK1_MODEL=domain`; сохраните эти экспорты. Пустой `__init__.py` сам по себе не является незавершённой бизнес-логикой, но тогда проверка через общий интерфейс domain не найдёт ваши классы. Не нужен сервер, база, API транспорта, сайт или ввод пользовательского кода в браузере.

В README своей работы запишите инварианты, команды запуска, выбранную политику ошибок и два решения, которые можете объяснить напарнику. Для нашей локальной версии достаточно передать папку без виртуального окружения; GitHub из оригинальной лабораторной не требуется для этой самопроверки.

## 2. Контракт Route

Конструктор: `Route(route_number: str, stops: list[str], base_fare: Decimal = Decimal("100.00"))`.

- Номер маршрута - непустая строка после удаления краевых пробелов.
- Тариф - конечный Decimal, положительный и кратный 0.01.
- Остановок хотя бы две; каждое название после удаления краевых пробелов непустое.
- Одинаковые соседние остановки запрещены. Возвращение на прежнюю остановку после другой допустимо: `A, B, A`.
- Снаружи можно прочитать номер, тариф и остановки; нельзя повредить модель изменением исходного списка или полученной коллекции.

Пример допустимых данных: номер `32`, остановки `Вокзал, Университет, Парк`, тариф `Decimal("100.00")`.

**Самопроверка:** создание с одной остановкой вызывает `ValueError`; изменение списка, переданного в конструктор, не меняет маршрут.

## 3. Контракт Bus

Конструктор: `Bus(plate_number: str, capacity: int)`; вначале пассажиров 0, маршрут не назначен.

- Госномер непустой. Для учебной версии удалите краевые и схлопните повторные пробелы: ` 123  AB 02 ` превращается в `123 AB 02`. Точная юридическая маска номера в PDF не формализована; дополнительные регулярные выражения здесь не требуются.
- Вместимость - именно целое число от 10 до 250 включительно.
- Всегда `0 <= current_passengers <= capacity`.
- `board_passengers(count)` с положительным целым количеством сажает пассажиров. При переполнении - `CapacityExceededError`, прежнее количество сохраняется.
- `leave_passengers(count)` с положительным целым количеством высаживает пассажиров. Если высадить хотят больше, чем есть, - `ValueError`, состояние прежнее.
- `assign_route(route)` принимает Route; `remove_route()` снимает маршрут. Назначение маршрута не сажает и не высаживает людей автоматически.
- Нельзя присвоить отрицательное число через публичное свойство пассажиров.

Для количества `0`, отрицательного числа или неверного типа операция отвергается. `True` не принимается как один пассажир - это уточнение адаптации.

## 4. Контракт TransitCard

Конструктор: `TransitCard(card_id, initial_balance=Decimal("0.00"), discount_rate=Decimal("0"))`.

- ID непустой, с удалёнными краевыми пробелами; публичного сеттера нет.
- Баланс - конечный Decimal, неотрицательный, кратный 0.01.
- Скидка - конечный Decimal в `[0, 1]`: 0 - нет скидки, 0.5 - половина тарифа, 1 - бесплатно.
- `top_up(amount)` работает только для незаблокированной карты; сумма минимум 100.00 KZT.
- `pay(fare) -> Decimal` принимает положительный базовый тариф. Итог `fare * (1 - discount_rate)` округляется до 0.01 через `ROUND_HALF_UP`; метод возвращает фактически списанную сумму.
- Если средств мало - `InsufficientFundsError`; баланс не изменяется. Ровно достаточного баланса хватает.
- `block(reason)` принимает непустую причину; после блокировки и оплата, и пополнение вызывают `CardBlockedError`, даже при скидке 100%.
- `unblock()` разрешает дальнейшие допустимые операции. Для отображения доступны баланс, скидка и признак блокировки, но не прямое присваивание.

В лекции метод называется `charge_fare()`, в лабораторной - `pay()`. В этой неделе используем `pay()`; это то же учебное действие, а не два независимых списания.

**Трассировка:** баланс 200.00, скидка 0.5; `pay(100.00)` возвращает 50.00, остаток 150.00. Затем попытка `pay(400.00)` отвергается, остаток по-прежнему 150.00.

## 5. Контракт SingleTripTicket

Конструктор учебного решения: `SingleTripTicket(price, issued_at=None)`. Он создаёт UUID-код; `issued_at` по умолчанию - текущее время UTC; `is_validated` вначале False.

- Цена - положительный конечный Decimal, кратный 0.01. Это уточнение задания, а не моделирование бесплатных проездных.
- `validate(bus)` принимает Bus и использует текущее время UTC.
- После успеха билет использован. Повторная валидация в этом же **или другом** автобусе вызывает `TicketAlreadyUsedError`.
- Для этой адаптации допустимый возраст: **0 <= возраст < 60 минут**. Ровно в 60:00 билет уже просрочен: `TicketExpiredError`. В PDF указан срок 60 минут без точной политики равенства; здесь граница выбрана явно.
- Время раньше покупки - `ValueError`. Время покупки и проверки должно содержать часовой пояс; смешивание naive/aware дат отвергается.
- При любой неуспешной первой валидации `is_validated` остаётся False.
- Для воспроизводимых тестов эталон допускает необязательный `validate(bus, now=...)`. Это небольшой параметр проверки, не обязательная архитектура часов. В рабочем вызове аргумент `now` не нужен.

Валидация билета сама не вызывает посадку пассажира: проверка билета и учёт количества - разные действия этой модели. Проверка повторного использования имеет приоритет над сроком: уже использованный билет остаётся использованным.


## 6. Полнота тестов и проверка именно своей модели

Самостоятельно напишите исходные пять сценариев:

| Имя | Наблюдение |
|---|---|
| test_card_prevents_negative_balance | InsufficientFundsError и прежний баланс |
| test_card_blocked_rejects_operations | И pay, и top_up вызывают CardBlockedError; баланс/блокировка прежние |
| test_bus_capacity_overflow | CapacityExceededError и прежнее число пассажиров |
| test_ticket_double_validation | Успех, затем TicketAlreadyUsedError; True сохраняется, включая другой Bus |
| test_route_minimum_stops | Одна остановка отвергается ValueError |

Дополнительно проверьте весь контракт: Route копирует входную/не выдаёт изменяемую коллекцию, соседние дубли/пустые строки/положительный тариф; Bus: 10/250, неверные 9/251, count: 0/−1/True/нецелый, высадку сверх наличия, assign/remove без пассажирских эффектов; Card: скидки 0/0.5/1, ровно достаточный баланс, пополнение 100/99.99, unblock/reason, отрицательные/NaN/Infinity/не-копейки/float и округление 0.01×0.5; билет: 59:59/60:00, будущую/naive дату, UUID/цену и иной Bus; свойства без сеттеров. Исключение без проверки после него не доказывает сохранность.

После своей попытки скачайте test_reference.py. Это предоставленный справочный набор, не ваши пять самостоятельно написанных сценариев. По умолчанию он проверяет соседний эталон. Для проверки именно своей domain-папки используйте явный выбор:

```powershell
# Выполнить из lab01_transit_domain. Укажите реальный путь к скачанному файлу.
$env:WEEK1_MODEL = 'domain'
python -m pytest 'C:/путь/к/test_reference.py' -v --import-mode=importlib
Remove-Item Env:WEEK1_MODEL
```

На macOS/Linux: `WEEK1_MODEL=domain python -m pytest /путь/test_reference.py -v --import-mode=importlib`. Импорт domain берётся из вашей текущей папки. Ошибка импорта/NotImplementedError — незавершённая работа; fallback к эталону при заданном WEEK1_MODEL отсутствует. В начале вывода -s можно увидеть точный выбранный файл: добавьте флаг `-s`. Свои тесты запускайте отдельно: `python -m pytest tests/ -v`.

Эталон отдельно (из корня сайта):

```powershell
python materials/week-01/examples/reference_solution.py
python -m pytest materials/week-01/examples/test_reference.py -q
```

Перед этим WEEK1_MODEL должен отсутствовать. Зелёный эталон не проверяет вашу папку. В собственном демонстрационном сценарии создайте Route/Bus/Card/Ticket, назначьте маршрут, оплатите/посадите пассажира, успешно проверьте билет, затем покажите отказ и старое состояние. Публичные методы имеют аннотации/docstrings, код соответствует PEP8; не удаляйте неудобные тесты ради зелёного результата.

## 7. Что сдать и как проверить друг друга

Передайте файлы domain, tests и короткий README. Не передавайте `.venv`, кэши, пароли или персональные данные. Напарник сначала читает контракт и запускает тесты, затем выбирает один успешный и один ошибочный сценарий для демонстрации. Не исправляйте чужую работу молча: верните воспроизводимый пример и ожидаемое поведение.

### Рубрика: 20 баллов

Блоки и максимум взяты из первой лабораторной; распределение внутри блока - прозрачная рубрика этой адаптации.

| Блок | За что начисляются баллы |
|---|---|
| Route + Bus: 5 | 2 - Route и защита остановок; 2 - посадка/высадка и границы; 1 - нормализация номера и назначение/снятие маршрута |
| TransitCard + билет: 7 | 2 - баланс/скидка/пополнение; 2 - pay, блокировка и сохранность при отказе; 3 - UUID/время/одноразовость билета |
| Тесты: 5 | По 1 за каждый из пяти обязательных сценариев, если проверка действительно обнаруживает соответствующую ошибку; сохранность состояния включается в сценарий, где применима |
| Защита: 3 | По 1 за объяснение трёх тем: класс/инвариант/инкапсуляция; Decimal и формула скидки; исключения и разбор отказа без повреждения состояния |

Баллы за правило выставляются по коду и наблюдаемому сценарию, а не за количество строк. Дополнительные тесты помогают доказать корректность, но не повышают максимум 20. Это учебная самопроверка, не официальная оценка преподавателя.

## 8. Защита и готовность

Объясните своими словами: зачем Decimal; что реально ограничивает property; почему нельзя менять пассажиров напрямую; чем InsufficientFundsError полезнее False. Продемонстрируйте отказ без изменения состояния.

Готовность: нет незавершённой бизнес-логики и отладочных print внутри методов; публичные операции имеют аннотации/понятные docstrings; код читаем и проходит тесты. Пустой класс исключения с docstring, который наследует стандартное поведение Exception, не считается неготовой функцией.
