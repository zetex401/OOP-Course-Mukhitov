# Практика 2. Расширяем терминал через SOLID и DI

Это авторская учебная практика к [лекции второй недели](theory.md). Она продолжает пример Avtobys; официальные исходные лабораторные преподавателя не заменяет. Все платежи и устройства здесь имитируются.

## Маршрут

Сначала пройдите [пошаговую инструкцию для VS Code](walkthrough.md). Она даёт готовые файлы, полный код, команды и ожидаемый вывод. Готовые блоки и 14 предоставленных тестовых случаев — учебный разбор. Самостоятельное задание ниже выполняется после него. Python запускается на вашем компьютере.

Практика — 60 минут: 0–10 подготовка и обязанности компонентов; 10–25 сборка готового примера; 25–40 подключение Bluetooth и запуск; 40–55 тесты успеха, отказа и неготового сканера; 55–60 объяснение направления зависимостей. При затруднении сохраните место остановки и текст ошибки. Это план, фактическое время группы не измерялось.

## Контракт учебного терминала

- Сканер сначала сообщает готовность. Если он не готов, чтение карты, расчёт тарифа и оплата не вызываются; результат False, красный индикатор и один звук ошибки.
- Готовый сканер даёт card_id; тарифный сервис возвращает конечный неотрицательный Decimal; стратегия process(amount) возвращает bool.
- При True терминал создаёт ровно одну успешную запись с card_id и суммой, показывает зелёный и даёт один звук успеха.
- При False нет успешной записи; показывается красный и даётся один звук ошибки. Отклонённое списание карты сохраняет её остаток.
- Терминал получает шесть зависимостей через конструктор. Конкретные классы выбирают в demo/bootstrap. Веток по имени способа оплаты внутри терминала нет.

Результат относится к указанным штатным сценариям. Сбой хранилища после оплаты, сетевые ошибки, повторная доставка запроса и атомарность не моделируются. Protocol не обеспечивает их автоматически.

## От готового примера к своей сборке

| Роль | Контракт / действие | Что меняете вы |
|---|---|---|
| PaymentStrategy | process(amount) принимает уже рассчитанную сумму и возвращает bool | Тестовый двойник наблюдает сумму; скидку в оплату не переносите |
| FareCalculator | compute_fare(card_id) возвращает Decimal | Свой StudentFareService выбирает учебный тариф по card_id |
| TransitTerminal | Получает scanner, fares, payment, repository, indicator, buzzer | Не меняете класс и process_tap |
| Внешняя сборка | Создаёт шесть объектов и передаёт их терминалу | Свой файл запуска или свой тест передаёт именно ваш объект fares и идентификатор STUDENT- |

bootstrap из solid_demo.py и assemble из предоставленных тестов фиксируют обычный FareService и обычный card_id. Повтор этих вызовов не подключает ваш сервис. Ориентир — явная сборка TransitTerminal в demo_week2.py: выберите нужные объекты снаружи. Конкретное тарифное правило, подключение и свои assertions реализуйте самостоятельно; готового решения здесь нет.

В собственном tests/test_student_fares.py используйте функции test_… и содержательные assert, а не return bool. Общий запуск из корня: `.venv\Scripts\python.exe -m pytest tests -q`. Убедитесь, что команда обнаружила ваши три случая вместе с 14 предоставленными; счёт 17 сам по себе не доказывает смысл проверок. При ошибке imports проверьте имена файлов и текущую папку по walkthrough.

## Самостоятельная работа — 60 минут

1. 0–20 минут: создайте файл student_fares.py с классом StudentFareService. Метод compute_fare(card_id) возвращает Decimal("50.00") для идентификаторов с префиксом STUDENT- и Decimal("100.00") для остальных. Это учебное правило скидки, не реальный тариф перевозчика. Подключите его через конструктор, сохранив TransitTerminal без изменений.
2. 20–30 минут: добавьте минимум три собственных теста: студенческий тариф; обычный тариф; полный проход студента с проверкой суммы в payment и в репозитории. Пользуйтесь тестовым двойником, не настоящим платёжным сервисом. Запустите собственные и предоставленные тесты вместе.
3. 30–40 минут: оформите README.md с командой запуска, наблюдаемым выводом и ответами защиты. Укажите, какие файлы и тесты предоставлены, а что добавлено вами.
4. 40–60 минут: выполните [онлайн-самопроверку](quiz.md), прочитайте объяснения ошибок, сохраните результат в свой текстовый файл. Перезагрузка сайта сбрасывает обе попытки; переходы между неделями и разделами сохраняют их в текущей вкладке.

## Отдельная ручная оценка — 0–20

| Часть | Баллы | Основание |
|---|---|---|
| Обязанности и зависимости | 0–5 | 2 за объяснение обязанности своего расчёта, 2 за объяснение шести зависимостей и передачу своего fares, 1 за указание своей точки сборки |
| Самостоятельное расширение | 0–7 | 2 за студенческий тариф, 2 за обычный, 2 за подключение без изменения терминала, 1 за Decimal |
| Собственные тесты | 0–5 | 1 за студенческий тариф, 1 за обычный, 2 за полный проход с точной суммой оплаты и записи, 1 за воспроизводимый общий запуск |
| Объяснение и README | 0–3 | 1 за команды и наблюдения, 1 за разницу DIP/DI, 1 за границы модели и атрибуцию готового кода |

Оценивайте собственные файлы, assertions и объяснение. Предоставленный constructor и 14 готовых случаев не дают автоматически /5 за понимание или /7 за расширение; онлайн-20/20 не подтверждает свой Python-код. Это учебная рубрика сайта. Ручные /20 и онлайн-/20 имеют разные основания; баллы не суммируются. Предоставленные тесты сами по себе не приносят баллы за собственные тесты. Автоматический запуск не заменяет объяснение.

## Что передать на взаимную проверку

Передайте напарнику файлы примера, student_fares.py, собственные тесты и README без .venv, __pycache__ и персональных данных; отдельно сохранённый онлайн-результат. Сайт ничего не отправляет автоматически.

Обратная связь: имя проверяемого; команда запуска; фактический итог тестов; наблюдение по каждой строке рубрики; балл /20; один конкретный дефект и способ его воспроизвести. Не пишите «всё работает», если сценарий не запускался. После исправления повторите затронутые проверки.
